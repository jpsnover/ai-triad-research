# Metric Provenance Register

**Ticket:** t/1343
**Author:** Computational Linguist

**Covers:** all 120 `CalibrationDataPoint` fields in `lib/debate/calibrationLogger.ts`, plus the node-level scoring instruments and CL-owned algorithmic parameters.

## Why this register exists

Every scalar the system emits implies a measurement instrument. This register classifies each one so that false precision is a visible, countable property of the system rather than a critique waiting to be written.

**Classes:**

| Class | Meaning | Evidence requirement |
|---|---|---|
| `metadata` | Session identity/context. Not an instrument. | none |
| `observation` | Direct count or ratio of system events with no embedded judgment beyond what to count. | none |
| `echo` | Records the parameter value a debate ran under. The *parameter* it echoes is classified in the Parameters table. | none |
| `stipulated` | Instrument or parameter asserted by design. No evidence pointer exists. | none by definition |
| `derived` | Value or formula produced by analysis of data. | pointer to the analysis |
| `human-validated` | Checked against human judgment. | pointer to the study |
| `validated-negative` | Checked against human judgment and found NOT to measure what it claims. | pointer to the study |

**Rule (no grade inflation):** anything without an evidence pointer is `stipulated` by definition. New metrics and parameters must declare their class at PR time and be added here in the same PR (enforced via the CL review checklist).

`crux_undecided_rate` (t/1676, landed `1228ad20`; type at `lib/debate/calibrationLogger/schema.ts:125`, computed at `calibrationLogger/extract.ts:417` — note `calibrationLogger` is a **barrel directory** post-t/1686, so cite the sub-modules, not the barrel): share of tracked cruxes terminating in `undecided`, meaning surfaced but never cross-engaged, or the iteration cap was reached before evidence sufficient to classify accumulated. Reads the **literal** terminal `crux.state` set by the debate-end finalization sweep rather than re-deriving it, which is what makes the sufficiency gate structural: `identified` with zero history transitions means never adjudicated, and any crux that reached `engaged`/`one_side_conceded`/`resolved`/`irreducible` is rejected from `undecided`. Notably the gate is **not** keyed on `speakers_involved`, which is universally ≥2 on identified cruxes and therefore carries no engagement signal (CL.Investigate1, t/1669#6). **stipulated** at introduction per the t/1669#2 design; promotes to `derived` only after the AC#2 golden-set absorption test establishes that `undecided` draws from *false* resolved/irreducible verdicts rather than cannibalising true ones. Baseline scan (`00649668`) predicts ~72.6% uptake (1,274/1,754 cruxes terminal-`identified`), which is high enough that the absorption test is the whole question — a verdict absorbing three-quarters of cruxes is either a real correction or a no-lose bucket, and the register should not record it as derived until that is settled. **Do not unify with the preference-layer `undecidable`** (`calibrationLogger` §5 / `synthesisPipeline.ts:155`): that one means "cannot order two claims' strength," this one means "the crux never reached a terminal decision." Distinct layers, deliberately distinct words. *(Outcome — this introduction-time record is superseded on promotion: the absorption test ran but the metric is **permanently stipulated, never derived** — see the FINAL `crux_undecided_rate` disposition below, t/1669 AC#4 closed e/45 (b).)*

`crux_addressed_rate` (explorationSummary `quality_summary`, `lib/debate/explorationSummary.ts`) — **semantics changed by t/1676 (`1228ad20`); values are not comparable across the cutover.** The denominator previously admitted any state ≠ `identified` over ALL cruxes; it now **excludes `undecided` from both numerator and denominator**, on the grounds that a crux which was never addressable should not count as a failure to address it (otherwise the metric double-counts the R-2 distortion the `undecided` verdict exists to remove). **Cutover: the first calibration run at or after `1228ad20`.** Anyone comparing a pre-cutover value to a post-cutover value is comparing two different instruments. Provenance is unchanged (**stipulated**) — this is a definitional change, not new evidence. **This field is distinct from `crux_addressed_ratio`** (neutral-evaluator, `calibrationLogger/extract.ts`), which is listed separately above and is the subject of the t/1796 partially-addressed defect. Two similarly-named crux-engagement metrics now exist on different layers; do not conflate them, and do not assume a fix to one touches the other.

`operational_closure_rate` / `operational_closure_per_speaker` (t/1537, `lib/debate/operationalClosure.ts`): per-speaker ratio of self-targeted to total engagement argument-network edges — how much a POV camp reproduces its own discourse (closure) vs. engages opponents (coupling). Same construct family as `peer_referencing_rate` / `camp_insularity_rate`, hence classified alongside them. The *counting* is mechanical, but the claim that a high self-targeted-edge ratio measures self-sealing debate is an asserted construct, unvalidated against human judgment or debate-outcome data — **stipulated** by the register's no-evidence-pointer rule. Path off stipulated (per design note `autopoiesis-operational-closure.md`, t/1536): correlate closure trajectories against `crux_addressed_ratio` / `claims_forgotten_rate` once enough debates log the field; promote to *derived* only if the correlation holds. `revoice_of` edges are excluded from both numerator and denominator (a restatement is not a genuine engagement move).

`crux_undecided_rate` (t/1676 `1228ad20`; engagement gate t/1818 `c070c980`; type `calibrationLogger/schema.ts`, computed `calibrationLogger/extract.ts`) — **PERMANENTLY stipulated; not promotable to derived by available measurement (t/1669 AC#4 closed 2026-07-28, e/45 decision (b)).** Share of tracked cruxes terminating `undecided` — the finalization sweep (`cruxResolution.ts`) sets `undecided` on a crux still in runtime `identified` at debate end that the engagement gate judges un-adjudicated. Intended construct: "surfaced but never *adversarially adjudicated*." That construct was measured against a frozen 30-crux golden set (`analyses/t1669-crux-undecided/`) under three operationalizations and **none reached the pre-registered ≥0.90 precision floor**: (1) structural proxy `state==='identified'` → **precision 0.20** (t/1676; ~24/30 terminal-`identified` cruxes were adjudicated in prose); (2) signal A, taxonomy_ref overlap → **0.20** (t/1818; 30/30 crux nodes are single-camp-anchored, so an opposing camp rebutting in prose shares 0 refs with the crux node by construction); (3) signal B, embedding max-sentence cosine → **ceiling ≈0.44** (t/1860 pre-sweep, τ=0.45). **Standing finding:** adversarial adjudication is a dialectical relation (rebut/concede/reframe) **not separable by available topical-co-presence instruments** (taxonomy refs or embeddings) — it occurs at low topical similarity (oblique rebuttal) and topical co-presence occurs without it (assert-and-echo); at a 6/30 base rate one false positive is ~10pp of precision, so the classes overlap irreducibly. A per-crux LLM-judge (the one non-co-presence instrument) was **rejected on evaluator-sensitivity grounds** (t/1835 MAD 0.625; t/1843/t/1846 — a judge-derived metric is evaluator-relative by construction). **Disposition:** the `undecided` *verdict category* is real and needed (it closes R-2/F-2), but the *rate* is reported **directional-only, permanently stipulated, never derived** — the academic paper does not cite it (zero occurrences of "undecided" in `docs/academic-paper-draft.md`), so the category suffices and no promotable rate is required; promoting one would be instrument sprawl. **Shelved, need-gated only:** (a) a *cap-terminated* structural sub-construct (precision ≈1.0 by construction but a narrower question, "still open at cap") may ship ONLY as a renamed `crux_cap_terminated_rate` — or with its operational definition stated verbatim at every citation site — never silently under this name; (c) the LLM-judge under the t/1860#7 protocol. Neither is scheduled. Full analysis: `analyses/t1669-crux-undecided/ac2-prereg-and-baseline.md` §RESULTS v1–v3. **Do not unify with the preference-layer `undecidable`** (crux terminal state vs. "cannot order two claims' strength").

**Engagement gate (t/1818, Option 1, 2026-07-27):** the finalization sweep now gates `undecided` on `wasCruxAdjudicated(crux, nodes, edges, transcript)` — adjudicated cruxes persist as terminal `identified` (status-quo-ante), only unadjudicated ones become `undecided`. Initial predicate (signal A, stipulated at introduction, parameterized in t/1818#2): each opposing camp in the crux's `speakers_involved` (≥2 opposing sides when more are involved) has ≥1 turn sharing ≥1 `taxonomy_ref` with the crux node, whole-debate window, no `identified_turn` floor (the floor was the root-cause bug). This gate's calibration was subsequently **refuted** (signal A precision 0.20 — see the `crux_undecided_rate` FINAL disposition above); this paragraph is retained as the code-provenance record of what shipped in `c070c980`, not an open promotion path.

`crux_addressed_ratio` and the neutral-evaluator crux-status labels — **measured rubric-wording sensitivity (t/1670 A/B, `analyses/PREREG-t1670-criterion-disclosure.md` Results, `c1529174`).** Rewriting the evaluator's status rubric (criterion disclosure, arm B) moved `addressed` from 73.3% to 100% (+26.7pp) while the unpatched convergence layer stayed flat and transcript hand-checks found both arms' true engagement near-ceiling. The status labels track rubric wording, not debate substance, so status distributions and `crux_addressed_ratio` are NOT comparable across evaluator prompt revisions; any evaluator-prompt change is a cutover for these fields. The disclosure sentence itself was NOT adopted (preregistered matrix, evaluator-relabeling row).

`affect_appropriateness` — **stipulated, with a known construct defect (t/1771, 2026-07-27).** `computeAffectAppropriateness` compares an absolute per-category intensity (`categoryScore`, observed weighted mean 0.080) against a normalized share (`AFFECT_PHASE_BASELINES`, each phase summing to ~1.0), so the deviation is dominated by the baseline vector rather than the debate. Measured consequences over 410 real debates: a zero-affect text scores 0.400–0.457 by phase; the observed minimum is 0.444 (the zero-affect value) with sd 0.035; Pearson r against `affect_intensity_mean` is 0.041. Evidence: `research/comp-linguist/analyses/t1771-affect-appropriateness-construct-defect.md`. **Do not promote this row to `derived` on the strength of a baseline refit** — fitting baselines against the current formula pins the metric near 1.0 corpus-wide (a no-lose bucket). **Construct fix landed: t/1785, origin commit `b1d39780`** (share-normalize `categoryScore` before the baseline compare, so both sides of the deviation are on the same scale). **Cutover: values from calibration runs at/after `b1d39780` are not comparable to earlier ones** — the pre-fix numbers measured the baseline vector, not the debate (r = 0.041 against `affect_intensity_mean`), so no trend may span the cutover. The row stays **stipulated**: the fix repairs the units mismatch, not the evidence base — `AFFECT_PHASE_BASELINES` and `MAX_ACCEPTABLE_DEVIATION` remain asserted values, and their re-derivation is t/1771 steps 2–3 (log per-category profiles, then re-derive), still blocked on profile logging. Excluded from the t/1342 validation study until re-derived baselines exist (t/1342#3); validating against asserted baselines would launder the assertion through the study.
