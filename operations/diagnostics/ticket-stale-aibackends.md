# Stale dist/server/aiBackends.js breaks OpenAI + DeepSeek backends

**Priority:** High — OpenAI and DeepSeek models are completely non-functional in the Electron app
**Assignee:** Taxonomy Editor / Tech Lead
**Related:** t/416 (DeepSeek timeouts), t/407 (DeepSeek model discovery)

## Summary

`taxonomy-editor/dist/server/aiBackends.js` is a hand-written file last modified **April 6, 2026**. The runtime IPC handler chain loads this file (via `dist/server/server.js` line 53), NOT the modern `src/server/aiBackends.ts` which properly imports from `lib/ai-client/`. All code changes to `src/server/aiBackends.ts` and `lib/ai-client/` have zero effect on the running Electron app.

## Root Cause

The stale file's `resolveBackend()` (line 51-57) only recognizes three backends:
- `claude` (prefix match)
- `groq` (prefix match)
- `gemini` (default fallback)

When `openai-gpt-5.5` or any DeepSeek model is passed, it falls through to `gemini`, then sends the model name to the Gemini API endpoint which rejects it. The `timeoutMs` parameter is `undefined` throughout, producing `NaN` in the error message.

## Evidence (Flight Recorder)

From `flight-recorder-2026-06-07T22-13-31.525Z.jsonl`:
- `bridge.generateText` called at t=27.2s with args `["...prompt...", "openai-gpt-5.5", null]`
- Failed at t=57.3s: `"OpenAI API request timed out after NaNs"`, `duration_ms: 30071`
- **Zero `ai.*` events** — no ai.request, ai.response, ai.error, or ai.retry recorded
- The stale code path has no flight recorder instrumentation

## Build Path Problem

- `npm run build:main` runs `tsc -p tsconfig.main.json` → compiles to `dist/main/`
- `dist/server/` is a separate, older directory — NOT regenerated by any build command
- `dist/server/server.js` line 53: `const ai = __importStar(require("./aiBackends"))` loads the stale file

## Fix

1. Delete `dist/server/aiBackends.js` and `dist/server/server.js`
2. Update `tsconfig.main.json` or the IPC handler imports so the runtime uses the compiled `src/server/aiBackends.ts` (which already has OpenAI, DeepSeek, Ollama support via `lib/ai-client/`)
3. Verify the IPC handler chain resolves to the new path
4. Add `ai.request`/`ai.response`/`ai.error` flight recorder events to the server-side AI path so retries, provider selection, and timeouts are visible

## Blast Radius

- **Broken:** All debates using OpenAI or DeepSeek models
- **Invisible:** All AI call internals (retries, timeouts, provider selection) — zero instrumentation in the stale code path
- **Unaffected:** Gemini, Claude, and Groq backends (they have inline providers in the stale file)
